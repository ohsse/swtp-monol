## 발견 사항

### 블로커 (높음) — **0건**

본 작업에서 블로커는 발견되지 않았다. Phase 4 검증 5건 모두 통과했고, 드라이런에서 에이전트가 3층 분류를 정확히 수행했다.

### 권고 (중간) — 2건

#### 권고 1. `standard-words.md` 의 `seq`/`ord`/`cnt` 의 "기본 데이터 도메인" 미등록

| 단어 | 현 표기 (기본 데이터 도메인 열) | 문제 |
|------|---------------------------|------|
| `seq` | `BIGINT` | `standard-data-domains.md` 에 해당 `DOM_*` 코드 없음 |
| `ord` | `INTEGER` | 동일 |
| `cnt` | `INTEGER` | 동일 |

**영향**: 신규 컬럼 설계 시 `seq`/`ord`/`cnt` 를 사용하면 데이터 도메인이 미확정 상태. `/dev:analyze` 에서 `DOM_SEQ_BIGINT` 등의 신규 도메인을 매번 논의해야 한다.

**해소 방안 (향후)**: `standard-data-domains.md` 에 `DOM_SEQ`(`BIGINT`), `DOM_CNT`(`INTEGER`), `DOM_ORD`(`INTEGER`) 3개 도메인을 추가 등록. 다만 초기 등록 10개 범위를 **의도적으로 제한** 했고, 이들 단어의 사용 빈도는 `nm`/`dtm` 대비 낮으므로 Phase 1 범위에 포함하지 않았다. 실제 사용 시점에 `/dev:analyze` 를 통해 자연 등록.

**판정**: 블로커 아님. ANALYZE1.md §PLAN 으로 전달할 결정 사항 의 "역공학 10개 한정" 결정을 준수.

#### 권고 2. `DOM_CODE_20` 의 enum 매핑 강제 부재

`DOM_CODE_20` 은 "공통 코드 필드, VARCHAR(20), NOT NULL" 로 등록되어 있으나 Java 측 enum 매핑 여부가 명시되지 않았다. 드라이런에서 `oper_stat_cd` 를 `DOM_CODE_20` 재사용 vs `DOM_OPER_STAT_20` 신규 분리 판단이 모호했다.

**영향**: enum 성격 코드(5~6 고정값) 와 자유 문자열 코드(20자 내외) 가 같은 데이터 도메인에 묶여 있어, 재사용 vs 신규 분리 판단을 매번 `wtp-dba-reviewer` 2차 승인에 의존한다.

**해소 방안 (향후)**: 데이터 도메인 2개로 분리 검토 — `DOM_CODE_20_ENUM` (enum 매핑 필수) vs `DOM_CODE_20_FREE` (자유 문자열). 단, 현 시점에는 실제 사용 사례가 축적되지 않았으므로 조기 분리는 오버엔지니어링 위험. 드라이런에서 판단 패턴이 3회 이상 반복되면 격상 ANALYZE.

**판정**: 블로커 아님. 판단 경로가 `wtp-dba-reviewer` 승인으로 명시되어 있어 실수 가능성 낮음.

### 참고 (낮음) — 3건

#### 참고 1. `rgstr` 만 유일하게 동사 형태 단어

`standard-words.md` 초기 등록 11개 중 `nm`·`dt`·`amt` 등 10개는 명사 약어, `rgstr` 만 동사(register) 로 등록. 일관성이 약간 깨지나 `rgstr_dtm`·`rgstr_id` 의 prefix 용도로 필요. 관찰만.

#### 참고 2. `/dev:analyze` 안건 매핑 표의 `wtp-glossary-manager + wtp-dba-reviewer` 동시 호출

새로 추가한 행 "신규 표준 데이터 도메인" 의 필수 호출에 두 에이전트가 동시 기재되어 있다. 기존 행은 모두 "필수 1개 + 선택 1개" 구조였는데, 이 행만 예외. Round 1 에서 두 에이전트 모두 호출되면 라운드 수가 기존 대비 증가.

**판정**: 정상 의도. "2차 승인" 이라는 게이트 특성상 Round 1 에 `wtp-glossary-manager` 의견 → Round 2 에 `wtp-dba-reviewer` 검증 형태로 자연 분리되므로 문제 없음. `/dev:analyze` 의 라운드 알고리즘(§4.2) 자체는 변경 불필요.

#### 참고 3. `CLAUDE.md` 의 `dict/README.md` 링크 경로

`CLAUDE.md` 의 "도메인" 용어 구분 경고 문단에서 `[.claude/rules/dict/README.md](.claude/rules/dict/README.md)` 로 참조. `CLAUDE.md` 가 프로젝트 루트에 있으므로 상대 경로가 올바름. 링크 테스트 생략 (실제 이동 필요 시 수동 확인).

### 즉시 적용 불필요 (이 작업 범위 밖, 별도 작업으로 검토)

2. **`DOM_CODE_20` 의 enum vs 자유 분리** — 사용 사례 3회 누적 후 ANALYZE 격상
3. **`wtp-glossary-manager` 출력 400단어 초과 대응** — 드라이런에서 ~600단어 생성됨. 사용 누적 후 에이전트 분리(Phase-이후 재검토) 또는 출력 템플릿 압축

이 PR 의 범위는 **사전 3층 구조 도입 + 하네스 3층 반영** 이다. 위 3개 제안은 모두 향후 사용 데이터 축적 후 수행할 사항으로, 현 범위에 포함되면 오히려 의사결정 품질이 떨어진다. **본 PR 로 종료 권장**.
